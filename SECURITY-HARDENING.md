# Усиление безопасности owleye

## Цель

Сохранить открытую регистрацию сессий через `OWLEYE_OPEN_SIGNUP=1`, но не позволять анонимным пользователям обращаться от имени сервера к произвольным адресам, заполнять диск, выходить за пределы каталога своей сессии или получать доступ к чужим записям.

Для каждой сессии одновременно действуют три ограничения:

- размер одного загружаемого файла — не более 1 MiB (`1 048 576` байт);
- суммарный размер файлов и метаданных — не более 10 MiB (`10 485 760` байт);
- срок хранения события — не более 24 часов.

Событие удаляется, когда выполнено хотя бы одно условие: оно старше 24 часов или после его сохранения сессия превысит 10 MiB. При превышении квоты сначала удаляются самые старые события.

## 1. Ограничение загрузок и хранения

### Конфигурация

Добавить настройки:

```dotenv
OWLEYE_MAX_UPLOAD=1048576
OWLEYE_SESSION_MAX_BYTES=10485760
OWLEYE_RETENTION_SECONDS=86400
OWLEYE_EVENT_RATE_PER_MINUTE=30
```

Безопасные значения выше должны использоваться по умолчанию и для основной, и для пользовательских сессий.

### Обработка загрузки

- Отклонять тело `POST /api/event` больше 1 MiB с кодом `413 Payload Too Large`.
- Учитывать в квоте GIF/JPEG, JSON-файл метаданных и соответствующую строку журнала.
- Перед записью проверять доступный объём сессии.
- Если квота будет превышена, сначала удалить самые старые события этой же сессии.
- Если освободить достаточно места невозможно, вернуть `507 Insufficient Storage` и не сохранять событие частично.
- Сериализовать проверку квоты и запись внутри одной сессии, чтобы параллельные запросы не могли обойти лимит.
- Ограничить `POST /api/event` до 30 запросов в минуту на сессию. При превышении возвращать `429 Too Many Requests` с `Retry-After`.

### Автоматическая очистка

- Запускать очистку при старте сервера, после каждой успешной загрузки и периодически не реже одного раза в 10 минут.
- Удалять медиафайл и связанный с ним JSON как одно событие.
- Удалять события старше 24 часов независимо от текущего размера сессии.
- При размере больше 10 MiB удалять события от старых к новым до достижения лимита.
- Не переходить по символическим ссылкам при обходе каталога.
- После очистки удалять пустые дневные каталоги.
- Ошибка очистки одной сессии не должна останавливать обработку остальных сессий.

## 2. Защита путей хранения

- Не использовать переданное клиентом `meta.at` как часть пути без проверки.
- Принимать только корректную дату в формате ISO 8601 и ограничивать допустимое отклонение от серверного времени.
- Для имени каталога использовать дату, вычисленную после разбора значения.
- Для имени файла использовать только безопасные символы или серверное время.
- После формирования пути проверять через `resolve`, что он находится внутри `<sessionDir>/events`.
- При нарушении возвращать `400 Bad Request` и ничего не записывать.
- Добавить тесты с `../`, абсолютными путями, обратными слешами, нулевым байтом и некорректной датой.

## 3. Защита исходящих запросов

### ntfy

- Для публичных сессий разрешить по умолчанию только `https://ntfy.sh`.
- Поддержать операторский allowlist через `OWLEYE_NTFY_ALLOWED_ORIGINS`.
- Разбирать URL через `new URL`, а не регулярным выражением.
- Разрешать только HTTPS, кроме явно включённого локального режима разработки.
- Запрещать loopback, private, link-local, multicast и служебные адреса IPv4 и IPv6.
- Проверять все IP-адреса, полученные через DNS, непосредственно перед соединением.
- Не следовать перенаправлению на запрещённый origin.
- Ограничить длину URL и запрещать логин и пароль внутри URL.

### Web Push

- Применить к endpoint такую же проверку протокола, DNS и IP-адресов.
- Убрать разрешение произвольного `http://localhost` в production.
- Не следовать перенаправлениям между origin.
- Ограничить число push-подписок на одну сессию.

## 4. Разделение прав доступа

Один идентификатор сессии не должен одновременно давать все права. Для каждой сессии создать независимые случайные ключи:

- `owner` — изменение настроек и управление ключами;
- `recorder` — отправка heartbeat и событий;
- `viewer` — чтение ленты и медиа.

Ключ `viewer` не должен позволять менять ntfy, добавлять push-подписки или загружать события. Ключ `recorder` не должен позволять читать архив. Все ключи должны иметь не менее 128 бит энтропии и поддерживать отзыв без удаления сессии.

## 5. Исключение ключей из URL и журналов

- После первого входа по `?t=` установить cookie и перенаправить на тот же адрес без параметра `t`.
- Не добавлять ключ к URL изображений, SSE, manifest и push-уведомлений.
- Не возвращать ключ из `/api/config`.
- Не печатать ключ или URL с ключом при запуске сервера.
- Настроить Caddy и nginx так, чтобы query string с `t` не попадал в access-логи.
- Устанавливать cookie с атрибутами `Secure`, `HttpOnly` и `SameSite=Strict`.
- Предоставить владельцу отдельное явное действие для создания отзываемой ссылки просмотра.

## 6. Безопасная открытая регистрация

`OWLEYE_OPEN_SIGNUP=1` остаётся поддерживаемым режимом.

- Ограничивать создание сессий по реальному адресу клиента.
- Доверять `X-Forwarded-For` только от настроенного reverse proxy, а не от произвольного клиента.
- Сохранить ограничение не более 5 новых сессий за 10 минут на IP.
- Добавить общий лимит регистраций в минуту для защиты от распределённой атаки.
- Удалять пустые неактивные сессии через 24 часа.
- Не считать адрес reverse proxy единым IP всех посетителей.
- Достигнув `OWLEYE_MAX_SESSIONS`, удалять только просроченные пустые сессии; активные сессии автоматически не удалять.

## 7. HTTP-защита

Добавить для всех ответов:

```text
Strict-Transport-Security: max-age=31536000; includeSubDomains
Content-Security-Policy: default-src 'self'; img-src 'self' blob:; media-src 'self' blob:; connect-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Permissions-Policy: camera=(self), microphone=(), geolocation=()
Cross-Origin-Resource-Policy: same-origin
```

Не возвращать клиенту текст внутренних исключений в ответах `500`; полный текст оставлять только в серверном журнале без секретов.

## 8. Тесты

Добавить автоматические проверки:

- файл размером ровно 1 MiB принимается;
- файл больше 1 MiB получает `413`;
- после превышения 10 MiB удаляются самые старые события только текущей сессии;
- событие старше 24 часов удаляется;
- параллельные загрузки не превышают квоту;
- одна сессия не может читать, удалять или учитывать в своей квоте файлы другой;
- traversal через `meta.at` отклоняется;
- ntfy и Web Push не могут обратиться к localhost, private и link-local адресам;
- редирект на запрещённый адрес блокируется;
- `viewer`, `recorder` и `owner` имеют только предназначенные им права;
- ключи отсутствуют в HTML, API-ответах, manifest, media URL и серверных логах;
- cookie содержит `Secure`, `HttpOnly` и `SameSite=Strict`;
- signup rate limit использует реальный IP за доверенным reverse proxy;
- обязательные защитные HTTP-заголовки присутствуют на HTML, API и media-ответах.

## Критерии готовности

- Открытая регистрация сессий продолжает работать.
- Пользователь не может получить записи другой сессии перебором URL или подменой пути.
- Анонимно созданная сессия не позволяет обращаться к внутренней сети сервера.
- Ни одна сессия не хранит больше 10 MiB и события старше 24 часов.
- Один запрос не может загрузить больше 1 MiB.
- Секреты не появляются в URL, журналах и клиентских API-ответах.
- Все новые проверки и существующий `npm test` проходят успешно.
